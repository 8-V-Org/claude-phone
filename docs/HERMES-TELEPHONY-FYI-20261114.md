## Deployed changes and lessons

### SIP framing and audio-fork control
- Equivalent of Hermes’s UTF-8 framing fix installed before requiring pinned drachtio-srf4.5.43. Receiver buffers bytes, slices complete length-prefixed frames in bytes, then decodes UTF-8. Version guard/idempotence; tests split Unicode/adjacent frames at every byte boundary. No dependency bump used as a shortcut. Credit to Hermes’s earlier finding.
- Replaced empty uuid_audio_fork capability invocation with help uuid_audio_fork. The empty probe itself caused mod_audio_fork Error with command(null)(null), including on calls that had working speech; that line alone did not prove failed media.
- Compatible deployed module stop_play always targets its default audio_fork bug, ignoring a custom bug argument. Start/stop/reset now consistently use audio_fork. Full fork stop/replacement on interruption clears prebuffer AND playout; stop_play alone clears only playout and is not proof all stale audio was removed. Startup and early interruption are serialized, preventing competing WebSocket expectations.

### Playback: latest targeted candidate is deployed, human acceptance remains open
- Gemini Live produces audio faster than realtime. Old480000-byte/10s application queue deleted queued speech on overflow; an earlier throw had ended calls. Owner’s nonfatal-overflow change stopped fatal overflow, but drop-oldest still lost words.
- Latest production path preserves FIFO bursts within a bounded60s total PCM capacity: normal application queue up to480000 bytes, then an anonymous unlinked0600 ring file capped2880000 bytes TOTAL, not60s plus10s. Still send at most960-byte24kHz PCM frames per20ms callback; do not dump an entire burst into native dynamically growing buffers.
- Temporary media-WebSocket backlog returns retryable false. Keep exact unsent frame queued and do not increment speech counters; distinguish a persistent2s stall from clean hangup.
- Send320ms paced zero PCM once after completed-turn speech drains. Compatible native reference batches incoming samples at1920*downscale_factor: up to240ms at native8kHz for24kHz output, despite a misleading120ms comment. A final short tail can remain stranded if no more bytes arrive. Padding is cancelled/rearmed for new audio and cleared on barge-in/close. It cannot synthesize words the provider never generated.
- Important limits: deployed-native source identity/audibility not attested by the public reference. Beyond60s capacity, measured nonfatal drop policy remains; hard call deadlines can abandon queued speech. Synchronous spill I/O is bounded in size, not filesystem latency; enqueue/read/tick-gap maxima are measured. Anonymous/unlinked is not guaranteed RAM-only or secure erasure; filesystem page cache/tmpfs can charge cgroup memory. No claim of universally lossless playback or complete silence-issue resolution.

### Tool acknowledgements and diagnostics
- Separate durable record_message save result from synchronous SDK sendToolResponse exceptions. A saved record must not be reported as storage failure or trigger a second response because acknowledgement submission threw. Receipt/submission/failure counters and regression tests cover this.
- @google/genai3.0.0 FunctionResponse.scheduling belongs at TOP LEVEL beside response for NON_BLOCKING functions. Blocking record_message replies omit scheduling; docs/SDK say it is ignored for blocking functions, so old presence is not established as a1011 cause. Do not move it into response based on conflicting tutorial examples.
- Log first PBX-facing SIP BYE origin, bounded known Reason metadata and SIP Call-ID, local duration-limit requests, provider close classification, pending bytes before cleanup, and model/turn completion separately from playback. A PBX-origin BYE can relay handset/carrier clearing; generic Call terminated does not identify ultimate initiator. SIP answer/job-completed does not establish good audio.
- Pass frame kind through output observer. Model speech, silence padding and consult cue have separate cumulative and post-save counters. Padding alone cannot emit first post-save speech-submission evidence. Socket submission does not prove semantic acknowledgement, native consumption, RTP delivery or human audibility.
- Provider turn-end known enums and numeric usage are logged without transcripts/payloads. One earlier1011 happened BEFORE any save attempt; a later save succeeded. Do not conflate these. maxOutputTokens512 is valid/restrictive but not proven causal; model, schema and token budget unchanged rather than speculative changes/paid reconnects.

- Soft local consult cue, lower priority than speech, starts after750ms; brief440Hz pulse every2.5s. Caller speech/barge-in stops cue without cancelling consult. No internal reasoning spoken and no extra provider call for cue.
- Approved-tier session-only SIP controls added with policy checks/cancellation: blind REFER, hold/second INVITE/REFER-Replaces attended signaling, park/unpark/pickup dial codes, presence profile and BLF SUBSCRIBE, voicemail dial codes/private PIN guard. REFER2xx is acceptance, not completion: require final NOTIFY. Attended signaling does not imply a private spoken consultation interval. Honor configured dial codes and licence differences; do not assume our FreeSMB limitations match Hermes.
