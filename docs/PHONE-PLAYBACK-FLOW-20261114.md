## Candidate repair
- Keep normal pending PCM at most480000 bytes in application buffers. When a burst exceeds that threshold, migrate pending/generated output to a bounded anonymous ring file (2880000 bytes total maximum,60s PCM). It is0600 inside0700 temporary directory; pathname is immediately unlinked, directory removed; fd closes on drain, barge-in and call end, and kernel cleanup covers process exit. Only generated output, not captured caller audio, is queued. This is transient buffering, not a persisted recording. An underlying tmpfs/filesystem page cache can still charge cgroup memory: this is not a zero-memory claim.
- Continue sending at most960 bytes per20ms callback. No native queue dump, catch-up burst, deadline extension, or model/token-budget change. Preserve original speech order and every byte for bursts within the total cap. The explicit extreme-cap overflow policy remains nonfatal drop-oldest/admit-head with audit; therefore this is NOT unbounded/lossless under every possible producer, and total queue latency may reach60s under overload. Routine short phone turns remain preferable.
- Add320ms paced zero padding ONCE after a completed model turn’s queued speech. Compatible native reference processIncomingBinary batches samples at streamingPreBufSize=320*downscale_factor*6; at24kHz downscale3 that is240ms despite the reference comment claiming120ms. Without more bytes, a short final prebuffer tail waits indefinitely. Padding flushes that simulated tail; it does NOT generate missing speech, certify the deployed binary’s source, prove RTP delivery or explain a many-second cutoff by itself. Native rendered acceptance is still needed.
- On a transient media WebSocket backlog, return retryable false and leave the exact next frame queued. The old tick removed the frame before send and treated any backlog as fatal. After2s continuous retryable stall, report explicit playback failure; closed/error sockets remain failures. Production send wrapper propagates false and does not count unsent bytes.
- Add enum-only provider turnCompleteReason/waitingForInput/interactionStatus and numeric usage counts, plus interruption origin/pending bytes. No text transcripts, tool arguments, PCM or credentials in diagnostics. These can distinguish a provider stopping generation (including a possible restrictive512-token-budget interaction) from client loss/interruption.512 is a valid setting; no evidence yet establishes it as the cause, so it remains unchanged. No automatic paid continuation/reconnect.
- Independent review found padding/cue could contaminate post-save speech evidence. Corrected by propagating frame kind through sendPcm: postSavePlayoutBytes/outputSpeechPcmBytes/playoutSubmitted count model speech only; outputPaddingPcmBytes/outputCuePcmBytes/postSavePaddingBytes/postSaveCueBytes count other frames separately. Only model speech can emit first post-save submission. outputPcmBytes remains all submitted PCM. An integration regression verifies padding/cue/rejected frames cannot masquerade as post-save speech. Submitted still does not mean heard.
- Synchronous spill I/O remains a bounded-size but not bounded-latency realtime risk. New max enqueue/read duration and max tick-gap counters measure it; do not claim async I/O. Review environment /tmp was overlayfs; production mount is unverified. Unlinking is cleanup/isolation, not guaranteed RAM-only storage or secure erasure.
