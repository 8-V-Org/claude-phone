## What consultation exposes / cue built
The current private bridge sends stream:false and returns one JSON result after the Gateway agent completes. It does not expose live titles/status events. The Gateway’s optional OpenAI SSE contract can expose public assistant text and function-call deltas, but these are not guaranteed progress-title events and are not internal reasoning. This change does not scrape or speak internal reasoning, switch the bridge protocol, or require a new API route.

ConsultCue provides a local soft 440Hz / 100ms single-tone pulse every 2.5s, beginning after 750ms of actual pending consult. It uses paced 24kHz mono PCM and requires no provider call. Model speech takes priority over cue frames. Completion, failure, call close, provider barge-in or locally detected caller speech stops the cue. Local speech detection operates only while a cue is active, so it also stops cue-only audio when Gemini does not emit an interruption event. Barge-in resets the native fork to flush buffered cue audio; the consultation itself is not blocked or automatically cancelled by the cue. Logs: consult-cue-start, consult-cue-stop, and consultCueSubmitted in call summary. Tone volume and speech threshold need a human audio check.

## Permission boundary
Phone tools are declared ONLY for approved-caller Live sessions and the runtime dispatcher/controller also enforces approved tier. Unknown callers remain message-only. Current owner-selected trusted-PBX/caller-list policy is unchanged; caller ID is not independent identity proof. Side effects require confirmed:true after the caller confirms the exact action/target. Per-call side-effect operations are serialized, idempotent per Live function-call ID, bounded by call lifetime, and not automatically retried after uncertain outcomes. These tools are not added to phone-mcp or the operator queue in this change.

## Tools
- phone_capabilities: reports current license/gates without reading secrets.
- transfer_blind: REFER on the PBX-facing call dialog; NEVER on the FreeSWITCH-facing endpoint dialog. A 202/2xx response is accepted, not completed. The listener is installed before REFER and waits for matching refer NOTIFY message/sipfrag final status. Missing final NOTIFY is TRANSFER_UNCONFIRMED; no blind retry. BYE alone is not completion proof.
- transfer_attended: caller hold via an explicit in-dialog re-INVITE, separate endpoint and second authenticated INVITE, then REFER with correctly oriented, URI-encoded Replaces after answer. Keeps the second dialog alive through final transfer notification. Failed consultation/transfer restores original caller SDP/audio where possible and closes the auxiliary leg. IMPORTANT: this implementation automatically hands off after the target answers; it does NOT provide a private spoken human-consultation interval or a prepare/complete conversation UI. Its tool description/result explicitly states that limitation.
- call_park: blind REFER to configured park code, default *0{orbit}, orbit 1–9.
- call_unpark: connect caller to retrieval code, default *1{orbit}{ext}, optional extension suffix.
- call_pickup: connect caller to default *20*{ext}, or *20* when extension omitted. PBX pickup permissions still apply.
- presence_set: defaults available=*30, away=*31, dnd=*32, custom1=*33, custom2=*34. Changes THIS ASSISTANT EXTENSION’s profile, not an arbitrary caller’s extension. PBX answer is a requested action, not independent confirmation that profile state changed.
- presence_watch: start/status/stop SIP Event:dialog SUBSCRIBE/NOTIFY, at most four per call. Uses trusted-source and known Call-ID correlation even for early notifications. Bounded XML, entity checks, full/partial versions and version-gap detection; state becomes unknown when stale/desynchronized. Refreshes subscriptions, handles bounded refresh 423/Min-Expires, unsubscribes with Expires:0 at cleanup. BLF call state is NOT registration, DND/profile or human availability. Tenant/SMB permissions and initial subscription rejection remain capability-detected.
- voicemail_leave: confirmed REFER to default *4{ext}.
- voicemail_check: dials default 999 and sends stored PIN by DTMF on the voicemail leg, then bridges caller to PBX/voicemail. AI capture/output is suspended for feature audio and restored if the feature leg ends. Missing PIN blocks BEFORE dialing. No spoken PIN request; no PIN in application logs, tool results or model context. A PBX/DTMF acknowledgement does not confirm successful IVR login.
- xapi_call_logs and xapi_recordings: unavailable stubs. Without xapi.json return XAPI_NOT_CONFIGURED. File presence changes the response to XAPI_ENTITLEMENT_AND_SETUP_REQUIRED, NOT a fake successful API connection. No XAPI credentials are read or HTTP request made. The owner-reported v20 SMB Free license is not entitled to current 8SC+ AI XAPI APIs. Adding a file alone cannot grant license entitlement.
- SMS is handled by the owner's custom SMS Cloudflare MCP server (portal server `sms` on ai-bot.8-v.org and ai-dev.8-v.org; Worker `sms.leland-cheung.workers.dev/mcp`; bearer auth via the existing MCP connection). Do not say SMS is unavailable and do not embed secrets. Supervisor barge/listen/whisper remain license-unavailable; no substitute console/API actions are attempted for those.

The installed drachtio-srf convenience dialog.refer/subscribe/notify shortcuts have an incorrect lexical this in this release; implementations use dialog.request and inspect final status instead. Native modify('hold') also has hold-state/failed-reINVITE queue bugs, so this code uses its own serialized dialog.request(INVITE) with parsed audio SDP and updates local/remote SDP only after 200.

## Configuration read only
phone.json is read from the existing protected mount; no values are changed. Optional dialCodes templates are honored under canonical keys call_park, call_unpark, call_pickup, voicemail_leave, voicemail_check, presence_available, presence_away, presence_dnd, presence_custom1, presence_custom2. Aliases park/unpark/pickup/voicemailLeave/voicemailCheck and older presence_lunch/presence_business_trip names are accepted. Templates support {orbit} and {ext}; false/null disables a code. Only digits, star, hash and recognized placeholders are accepted; invalid policy fails closed.

Internal destinations are digits (2–8), self-transfer is rejected, optional dialPolicy.internalAllowlist narrows them. PSTN transfers require BOTH dialPolicy.allowPstn=true and exact membership in dialPolicy.pstnAllowlist using explicit E.164. No 9 or other prefix is inferred. Operator outbound dial behavior remains unchanged. No PSTN test was requested or performed.

Optional voicemail PIN filename defaults to /run/phone-secrets/voicemail-pin (existing host secret directory mount); phone.json voicemailPinFile may name a basename in that directory only. Must be a private nonsymlink regular file with no group/other permissions, 3–20 digits. Optional voicemailPinDelayMs is bounded 1000–15000ms, default 3000ms; IVR timing is unverified until human test. No PIN file is present at this rollout.
