# Live audio and Drachtio framing fix — 2026-11-13

## Root causes and scope
1. The old capability check called endpoint.api('uuid_audio_fork',''). The module logs Error with command (null) (null) before returning usage. That error is generated by our own empty probe, not proof of failed media: earlier owner-observed spoken calls had the same line. Check API registry help instead: endpoint.api('help','uuid_audio_fork'). Capability requirements remain enforced.
2. The matching bidirectional module implementation initializes bugname to MY_BUG_NAME=audio_fork. Its stop_play branch does not read an explicit bug argument, unlike stop/pause/resume. Our custom phone_live bug therefore could not be found on interruption. Native help advertises stop_play but does not reveal this naming limitation. live-fork.js now uses audio_fork consistently and sends stop_play against the default, then fully stops/restarts that fork to flush both buffers. Start includes explicit empty JSON metadata and 16k input/24k bidirectional raw streaming options.
3. Initial media startup and early model interruption are now serialized, avoiding competing pending WebSocket expectations/fork starts for one channel.
4. Pinned drachtio-srf 4.5.43 sends byte lengths correctly, but its receiver used a UTF-8 string and Unicode-code-point slicing. A display name containing multibyte UTF-8 could stall a complete response and consume bytes from the following frame. lib/drachtio-byte-framing.js is installed in index.js before require('drachtio-srf'); it keeps sockets binary, parses byte headers, and decodes each complete payload only after byte slicing. It preserves upstream connect/error/reconnect/close handlers. Dependency version/lockfile unchanged; the patch is version-guarded and idempotent. Invalid frames close the control socket with a credential-free error, not a dump of SIP data.

Reference inspected for native command behavior: https://github.com/W1ck3dZA/mod_audio_fork/blob/main/mod_audio_fork.c and mod_audio_fork.h. This public compatible fork is reference evidence, not a claim of source-identity attestation for the host image. Actual default-bug stop/reset behavior was verified on the deployed native module below. No module replacement or FreeSWITCH rebuild was required.

## Diagnostics
Private voice logs now contain lifecycle stages, actual redacted underlying error messages, Google setup completion/close status, fork start acknowledgement, WebSocket connection/rejection/close code, first input/output PCM, media-reset count and a final call summary. Known environment credentials, bearer values, URL key/token parameters and unpredictable media WebSocket URLs are redacted. PCM content/transcripts are not logged by these counters. Errors are preserved through LivePlayout instead of replaced with a generic Playback reset failed. An unexpected provider close is a failure, not a clean SIP hangup.

A SIP hangup, provider termination and media failure are separately labelled. The final summary includes inputPcmBytes, modelPcmBytes, outputPcmBytes and mediaResets; byte counts prove application transport flow, not that a human heard correct/intelligible audio.
