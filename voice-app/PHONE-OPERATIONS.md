# Hermes phone service

## Access tiers

Bootstrap loads the protected phone.json into the service environment. The app never changes that file.

Incoming SIP must match a configured trusted source and the configured destination extension. Only then is the SIP From user compared exactly against the configured caller allowlist. An allowlisted caller receives full conversational access through the Hermes bridge, with normal agent approval/safety rules. Everyone else, including anonymous callers, receives message-taking only. The Live model cannot elevate its own tier: the tool router rejects consult calls for message-tier sessions even if it fabricates a function call.

The global consult enable flag does not bypass per-call classification. Unknown callers are denied in legacy batch mode, which does not implement this message-only path.

Approved callers' substantive requests are forwarded automatically, without a magic phrase or FAQ ID. For the Hermes loopback API on 8642, the bridge uses `hermes-agent` and a random per-call `X-Hermes-Session-Id`. The same ID continues history during that call; a separate call receives a different ID. The older `user: phone-...` field alone does not provide Hermes session continuity.

## Private messages

The default store is `/app/messages` in voice, mounted to the host inbox. It requires explicit `consent: true` plus nonempty name, callback and reason. The assistant must collect details, read them back and obtain affirmative consent before invoking `record_message`.

Saved JSON is published atomically with mode 0600 in a 0700 directory. IDs and timestamps are generated by the server. Message text is not written to application status logs. Failures return an unsuccessful tool result and write underlying filesystem error codes to private logs. No tool invocation and a failed save are distinguishable via `[PHONE_MESSAGE] save-requested`, `save-confirmed`, and `save-failed` events.

The store is bounded to 1000 records by default and never deletes old messages automatically. Concurrent writers serialize using a private `.write-lock` directory. A process crash can leave this lock behind; an operator must check for an active writer before removing a stale lock. This fails closed rather than silently dropping messages.

## Authenticated local control

Live mode starts a loopback-only HTTP API on its existing HTTP port (default 3000), plus an authenticated Unix socket `/app/messages/phone-api.sock`. The socket is visible inside Hermes at `/opt/data/phone/phone-messages/phone-api.sock`, avoiding host/network-namespace changes. Both require the existing protected bridge bearer token; never put that value in chat, command arguments, or source.

Use the client, which reads the token from its protected file internally:

```sh
node /opt/data/phone/claude-phone/voice-app/phone-api.cjs health
node /opt/data/phone/claude-phone/voice-app/phone-api.cjs probe
node /opt/data/phone/claude-phone/voice-app/phone-api.cjs validate 30911
node /opt/data/phone/claude-phone/voice-app/phone-api.cjs validate 6174449080
node /opt/data/phone/claude-phone/voice-app/phone-api.cjs dial 30911
node /opt/data/phone/claude-phone/voice-app/phone-api.cjs dial +16174449080
node /opt/data/phone/claude-phone/voice-app/phone-api.cjs status CALL_ID
node /opt/data/phone/claude-phone/voice-app/phone-api.cjs hangup CALL_ID
```

`probe` writes an explicitly synthetic, consented deployment verification record through the running voice service. It returns its ID; verify the corresponding JSON and mode from the mounted host inbox. It is not evidence of a successful spoken consent interaction.

HTTP equivalents: authenticated `GET /health`, `POST /api/messages/probe` with `{}`, `POST /api/outbound-call` with `{"to":"30911"}`, and `GET /api/outbound-call/CALL_ID`.

An accepted outbound request is not an answered call. Read lifecycle status to distinguish dialing, active, completed, cancelled and failed. `POST /api/outbound-call/CALL_ID/hangup` with `{}` stops a call; the client exposes this as `hangup`. Cleanup is bounded and may keep the shared slot occupied briefly after cancellation (up to the setup cleanup deadline). Outbound shares the same one-call lock as inbound. The callee receives approved-tier access only if the dialed number is itself allowlisted; owner-authentication of the dialing API does not grant arbitrary recipients access to the full agent.

Dialing uses this extension's identity and digest credentials through the configured 3CX registrar. There is no legacy hardcoded trunk host and no added `9` prefix. There is no outbound destination allowlist and no application rate limit. Outbound shares the one-call lock with inbound (`409` `call_busy`). The policy call-length ceiling is 20 minutes (1200000 ms); a 30-second setup/ring timeout remains. `GET /health` reports `allowPstn`. `validate` / `{to,dryRun:true}` checks a destination without placing a call or taking the slot. When `PHONE_OUTBOUND_ALLOW_PSTN=true` (already set on this host), destinations may be an extension (1–8 digits), a 10-digit NANP number, an 11-digit number starting with `1`, or explicit `+1` NANP. Those PSTN forms normalize to `+1` and are dialed literally. International country codes are rejected. Outbound PSTN is NANP +1 only (10-digit, 11-digit, or +1). International country codes are rejected. Blocked Caribbean/premium NPAs: 242, 246, 264, 268, 284, 345, 441, 473, 649, 658, 664, 721, 758, 767, 784, 809, 829, 849, 868, 869, 876, 900, 976 (US territories 340/787/939 remain allowed). Policy call-length ceiling is 20 minutes (1200000 ms). 3CX still enforces trunk, outbound-rule, and license limits. SMS is not a 3CX SIP send API. Use the owner's custom SMS Cloudflare MCP server: portal server `sms` on ai-bot.8-v.org and ai-dev.8-v.org, Worker `sms.leland-cheung.workers.dev/mcp`, bearer auth via the existing MCP connection. Do not embed or request secrets, and do not say SMS is unavailable. The phone-mcp Worker path for 30910 is a separate surface and is not enabled by this client.

## Deployment constraints

Only use scoped `phone-ctl` commands. Keep the gemini-api v0.4.5 Linux_arm64 URL and checksum unchanged. No host compose, phone.env, phone.json or Caddy changes are required for the app deployment.

After a Portainer redeploy of Hermes, recreate phone-bridge because it shares Hermes's network namespace. Preserve the phone source and inbox mounts in the host stack. Container uptime, SIP REGISTER success, an API storage probe and unit tests do not establish real two-way speech, barge-in, or human consent behavior; those need controlled call tests.
